# TestDisk fork — consolidated audit findings

**Repository** [keykei2010-lang/testdisk](https://github.com/keykei2010-lang/testdisk)  
**Reviewed build** [`d731c21`](https://github.com/keykei2010-lang/testdisk/commit/d731c21071a3f71e5adab66c553e370a460c85b3), published November 26, 2026. The only tracked change since the attached report’s `365cfff0` was an image asset.

This list merges the attached issue report and the second audit. Reproductions used Linux and disk images or fixtures. The 27 repository tests, type-check, lint, and Vite build passed. Windows packaging succeeded in CI. Live Windows recovery was untested.

## Scan coverage and Windows I/O

1. **Raw reads violate sector alignment.** NTFS samples and $Bitmap reads, FAT/exFAT metadata, and small carving probes use unaligned requests. Windows logical-volume handles can reject these even when elevated. Physical-drive behavior was untested. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1344)
2. **One raw-read error can abort Quick Scan.** NTFS read failures can escape the scanner before results are returned. Desktop, folder, and emptied Recycle Bin searches share this path. A physical-drive error can be misreported as an elevation problem. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1628) · [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1250)
3. **Deep Scan can report 100% after an incomplete read.** Reproduced with only 512 bytes read out of a declared 1 MiB. The parent ignores worker error messages and can count both error and exit for one worker. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2626)
4. **One failed chunk can skip the rest of a worker’s range.** The worker breaks out on a failed or very short read, with no smaller retry or record of the skipped range. [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L414)
5. **Quick Scan caps coverage without a clear warning.** Native NTFS stops at 250,000 records across partitions. Folder and Recycle Bin lookup uses 180,000 per call. Sleuth Kit fallback inspects at most six targets and 4,000 entries each and can accept partial listing output after an engine error. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1385) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1668) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2491) · [enginesHelper.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/enginesHelper.cjs#L223)
6. **Unallocated-only mode can scan unverified space.** Reproduced with no bitmap. Missing coverage is treated as free, and the Quick Scan continuation starts a new job that skips bitmap collection. [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L36) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2443) · [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L3433)
7. **Pause and cancel can lag.** Synchronous Quick Scan work blocks control requests, and long deep-scan format probes can delay pause. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2385) · [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L392)

## Wrong or incomplete results

8. **Carved sizes can be guesses marked complete.** Fixed caps or defaults across multiple format branches can truncate files or add unrelated bytes while receiving high recovery scores. A 24,229,045-byte MKV was reported as 16,777,216 bytes with no truncation flag. WebM, RAR, 7z, and legacy Office also use guesses. [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L544) · [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L581)
9. **Guessed sizes can hide other files.** The carver skips ahead by the proposed size within a read window, potentially skipping valid headers. [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L700)
10. **NTFS attribute lists are ignored.** The native parser does not follow extension records, so it can miss data runs belonging to some fragmented files. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1186)
11. **NTFS compression and file-level encryption are unchecked.** The native parser reads unnamed data runs without handling or flagging these attributes. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1232)
12. **NTFS record size and sector geometry are hard-coded.** The native scanner assumes 1,024-byte MFT records. Several partition and device paths assume 512-byte sectors, limiting compatibility with other layouts, including native 4K sectors. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L591) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1385)
13. **Incomplete allocation checks can inflate recovery confidence.** The NTFS bitmap is capped at 8 MiB, covering about 256 GiB at 4 KiB per cluster. An extent outside the bitmap was reproduced as marked intact, a flag that can yield a 98% score. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1264) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1513) · [recoveryHealth.ts](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/engine/recoveryHealth.ts#L100)
14. **Folder and shadow-copy results can use the wrong scope.** Folder matching uses a substring. VSS examines three snapshots globally without first restricting them to the requested volume, and nested paths can be flattened or omitted. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1568) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1690)
15. **Carved deletion status and dates can be misleading.** Whole-disk hits are labelled deleted even if they came from live files. Missing timestamps can become the scan time in native and in-memory results, and native export can apply that date to the saved file. [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L700) · [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L492) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L3106)

## Export integrity and data safety

16. **Short or empty exports can be reported as verified.** Reproduced 512 of 1,024 requested bytes and a separate zero-byte export. Both were saved and counted as verified with no warning. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2958)
17. **CRC verification can mislead or contradict the result.** The check covers at most the first 64 KiB, usually before repair. Files without a check can count as CRC-verified. A reproduced mismatch generated a warning but still published the file, counted it as saved, and logged it as OK. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2989) · [RecoveryModal.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/components/RecoveryModal.tsx#L293)
18. **Portable ZIP can silently package incomplete or incorrect bytes.** The reader rounds offsets and lengths down and caps regular reads at 128 MiB and Sleuth Kit reads at 16 MiB. The ZIP path accepts short reads and can zero-fill missing extent bytes. A three-byte request returned 512 bytes in testing. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2074) · [RecoveryModal.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/components/RecoveryModal.tsx#L385)
19. **Sleuth Kit export skips expected-length verification.** Successful icat output with any positive byte count can be counted as verified. Its destination stream lacks a write-error handler. [enginesHelper.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/enginesHelper.cjs#L293) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2912)
20. **Same-source write protection is incomplete.** Native export checks one source, logical-volume checks compare letters, and physical-drive checks allow unresolved destinations. ZIP downloads, report writes, and media-repair temp files bypass that guard. The README suggests a different folder, which can still be on the source filesystem. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2688) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L1823) · [RecoveryModal.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/components/RecoveryModal.tsx#L466) · [README.md](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/README.md#L67)
21. **Repair-on-save retains only one output.** When repair succeeds, the export publishes the repaired bytes without automatically saving the untouched extraction alongside it. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L3007)
22. **No dedicated drive imaging or bad-sector retry.** The app lacks an acquisition workflow for failing drives. Parallel readers may add strain on failing hardware. That impact was unmeasured. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2573) · [scannerWorker.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/scannerWorker.cjs#L414)
23. **No user-facing SSD TRIM warning.** The reviewed app and documentation omit the risk that a deleted filename can survive after the SSD stops returning the original bytes. [README.md](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/README.md)

## Partitions, credentials, and reports

24. **Lost-partition search sees only the first MiB in streaming mode.** Physical disks and images above 128 MiB use a 1 MiB prefix for initial lost-partition analysis. An unlisted boot sector at LBA 2048 on a 512-byte-sector disk falls just outside it. Native metadata scanning uses detected and listed volume starts. [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1042) · [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1220) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L522)
25. **A repaired image may contain only the first MiB.** Restore patches the in-memory bytes, which can be just the scan prefix for a streamed source. The exported image can therefore be only that prefix. [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1638) · [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1779)
26. **The partition writer only handles four primary MBR entries.** It sorts and keeps up to four entries, with no GPT repair. Applying it to a GPT-derived layout can produce an unsuitable partition table in the exported copy. [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1638) · [partitions.ts](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/engine/partitions.ts#L554)
27. **BitLocker password flow and credential handling need correction.** The ordinary password is passed as a trailing argument to an option documented as an interactive prompt. The recovery password is also placed on the child process command line. Native unlock was untested. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2163) · [Microsoft command documentation](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/manage-bde-unlock)
28. **Saved sessions lose data and cannot genuinely resume.** Exports silently cap items at 5,000, omit discovery CRCs and Sleuth Kit inode IDs, and may save only a sample for memory-backed files. Import shows 100% without reconnecting the scan target. [App.tsx](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/App.tsx#L1972)
29. **DFXML output is invalid XML.** Reproduced even with an empty result list. The generator uses dc:type without declaring the dc namespace. [dfxml.ts](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/src/engine/dfxml.ts#L16)

## Build, dependencies, and documentation

30. **Elevated helper discovery trusts user-writable paths.** Helper lookup can fall back to AppData, per-user package locations, and PATH without verifying the executable. This is a trust risk when running as administrator. [enginesHelper.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/enginesHelper.cjs#L28)
31. **Helper downloads lack checksum verification and consistent pinning.** CI downloads a rolling FFmpeg build, and the local setup uses different sources or versions for FFmpeg and Sleuth Kit. Neither reviewed download path checks expected hashes. [build-windows.yml](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/.github/workflows/build-windows.yml#L31) · [setup-win-engines.ps1](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/scripts/setup-win-engines.ps1)
32. **Missing helpers can still produce a green build.** CI catches download failures and continues, so a successfully published package can lack an engine. [build-windows.yml](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/.github/workflows/build-windows.yml#L38)
33. **Windows build dependencies are not reproducibly installed.** CI uses npm install and installs Electron and electron-builder without pinned versions. [build-windows.yml](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/.github/workflows/build-windows.yml#L24)
34. **Windows release is unsigned.** The reviewed build logs explicitly show that signing was skipped. [Windows build log](https://github.com/keykei2010-lang/testdisk/actions/runs/45788338581/job/139800731514)
35. **README promises automatic elevation that packaging does not request.** The UI has a separate elevation action. The Windows package does not configure the automatic administrator launch described in the README. [README.md](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/README.md#L59) · [package.json](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/package.json)
36. **Upstream branding obscures which recovery engine runs.** CI bundles official TestDisk and PhotoRec, while the app’s main recovery paths use custom code with optional helper integration. The TestDisk/PhotoRec name, 7.2.x version and org.cgsecurity app ID can imply an official release. [package.json](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/package.json) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/electron/main.cjs#L2409)
37. **Bundled-engine licensing needs separate verification.** The source review raised checking binary redistribution obligations. These reviews did not establish a license violation. [README.md](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/README.md) · [build-windows.yml](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/.github/workflows/build-windows.yml#L31)
38. **The test suite misses the desktop scan and export entry points.** The 27 repository tests exercise engine components but do not load main.cjs or scannerWorker.cjs. The audit’s separate Linux probes exposed failures outside that suite. [recoveryEngine.test.ts](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/tests/recoveryEngine.test.ts)
39. **Windows CI does not gate releases on validation.** The publish job runs neither tests nor lint/type-checking, and no native Windows drive recovery smoke test was found. A successful package establishes build success. Live NTFS, FAT32, and exFAT behavior remains unverified. [build-windows.yml](https://github.com/keykei2010-lang/testdisk/blob/d731c21071a3f71e5adab66c553e370a460c85b3/.github/workflows/build-windows.yml) · [Windows build](https://github.com/keykei2010-lang/testdisk/actions/runs/45788338581)
