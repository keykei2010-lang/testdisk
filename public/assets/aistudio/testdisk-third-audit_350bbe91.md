# TestDisk fork — third audit

**Revision** [`20fca16`](https://github.com/keykei2010-lang/testdisk/commit/20fca1623e7c8be961069f8d1625e052745aaee9) on `master`, checked November 26, 2026. This revision is published as **Disk & Partition Recovery Explorer 1.0.0** in [dev-build](https://github.com/keykei2010-lang/testdisk/releases/tag/dev-build). The comparison baseline is the 39-item audit of `d731c21`.

## Verdict

The new release addresses many earlier issues. It rejects ordinary short native exports and CRC mismatches, adds bad-sector retry and warnings, makes normal reads sector-aligned, disables prefix-only partition repair, fixes DFXML parsing, and runs tests in Windows CI. It still has repeatable failures in scan coverage, exported byte counts, and lost-partition delivery. I would use it as a secondary tool on a disk image and would require a native Windows acceptance run before relying on live-drive recovery.

## Verification

- **Linux locally** — 31 repository tests, TypeScript, ESLint and the Electron-mode Vite build passed. I ran additional tests with the real scanner workers, the desktop IPC handlers with a stub Electron shell, and generated or known-answer disk images. Fault injection simulated read errors; it did not access failing hardware.
- **Known-answer recovery** — the native NTFS path recovered all 12,032 bytes of `Important.bin`. SHA-256 matched `833d518b36e9b97849398241881ea06f37c70ecb2d7b1c6d2af78c44ea2cb973`. Exact unaligned slicing, ordinary short-export rejection, mismatched-CRC rejection, and namespace-aware DFXML parsing also passed. The generated 24,229,045-byte MKV still produced a 16,777,216-byte carve, now correctly marked estimated and truncated.
- **Windows CI** — 31 tests passed on the Windows runner and packaging succeeded. I did not run the packaged app, access Windows raw volumes, or test BitLocker unlock on Windows. ## Highest priority

1. **Lost-partition results never reach the desktop.** High · Reproduced through IPC. The helper returned a partition at LBA 2048, but the IPC response had no partitions property. The helper returns an array, the caller reads found.partitions, and the UI silently catches rejection. With mmls available the handler dereferences undefined before responding. Its fallback additionally expects lengthBytes, which the mmls parser never returns. The helper’s result shape and Lost (Found) status also differ from the UI’s PartitionEntry contract. 2. **Deep Scan still reports complete on early EOF.** High · Reproduced through IPC. A 1,024-byte source with a declared size of 1 MiB reported 100%, incomplete=false and no warnings. The parent checks cancellation and reported errors, but does not reconcile expected coverage with the bytes actually read. Worker error handling and duplicate accounting did improve. An EOF can still finish without an error message. A simulated EIO when reading the real 1,536-byte $Bitmap converted it into an all-zero map with no warnings. The parser publishes the zero-initialized buffer after failed reads, so overwritten data can be marked intact and live clusters treated as free. The new bounds check helps past the end of a bitmap but cannot detect unreadable bytes inside it. ## Additional findings

9. **Selected-folder and Desktop shadow copies are filtered out.** High · Source review. VSS requests a drive-letter match via volLetterByGuid. The folder/desktop caller supplies a drive letter but leaves that map empty, so its filter rejects every shadow copy. The Recycle Bin path provides a map separately. Directory-boundary matching and nested VSS paths were improved. The remaining snapshot limit uses the last three returned records with no timestamp sort, and same-path versions collapse into one. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L2214) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L3203) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L3290)

10. **NTFS extension records can be combined without ownership or continuity checks.** High · Source review. General attribute-list support is present. It follows record numbers without validating the referenced sequence number or that the extension points back to the expected base record, then sorts and concatenates found VCN segments without proving continuity. An unreadable or reused extension can yield an incomplete or wrongly assembled candidate. The MFT bootstrap reads the base record’s data runs directly and lacks equivalent extension handling. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L1450) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L1643) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L1858)

11. **Sleuth Kit can look up a different sector than the one it listed.** Medium · Source review. fls receives the discovered sector size, but native preview and extraction callers do not pass that size to the helpers. A byte offset for a 4 KiB logical-sector disk can therefore be converted with the default 512-byte divisor. icat also rejects short output but still accepts output larger than the known size. The quick-stage deduplication key ignores the partition, so identical paths and sizes on different volumes can collapse. The normal raw export path still streams the bytes under the original file extension without decompressing or decrypting. Treat the output as a raw extraction unless a separate tool validates it. [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L1721) · [main.cjs](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/electron/main.cjs#L4116) · [recoveryHealth.ts](https://github.com/keykei2010-lang/testdisk/blob/20fca1623e7c8be961069f8d1625e052745aaee9/src/engine/recoveryHealth.ts#L108)

13. **Lost-partition probe has sparse coverage and weak validation.** Medium · Reproduced on test image; limits from source. The helper found a candidate at LBA 2048 but missed one at LBA 5000 in the same 8 MiB image. It stops at 256 GiB, probes selected LBAs and a MiB-based stride, and tolerates boot-sector geometry that places a candidate beyond the source. Its native signature branches handle NTFS, exFAT, BitLocker and FAT32. The documented FAT12/16 and ext4 lost-partition coverage is broader than these branches. 14. **MBR export still needs overlap, range and slot validation.** Medium · Source review. The streaming prefix export is blocked, and the writer refuses detected GPT headers and protective MBRs. On a full MBR image, merging and sorting proposed entries can still discard entries beyond the first four. The writer lacks an overlap check and uses unsigned 32-bit coercion for start and size, without checking source bounds.
